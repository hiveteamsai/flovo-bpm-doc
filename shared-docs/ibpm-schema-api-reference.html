Bölüm 1 — Veritabanı Şeması

Kanonik entity deseni: id uuid PK, organization_id uuid NN FK→tenants, code text NN, definition text NN (görünen ad), translation_code text? (i18n, translation.code'a bağlanır), created_at/updated_at. + Yaşam-döngüsü: active, deleted, sync_status ve partial-unique (organization_id, code) WHERE deleted=false.

Notlar / belirsizlikler (accuracy)

  1. İki users-benzeri tablo: platform public.users (auth kimliği) vs public.org_users (org-directory çalışan, /v1/users kaynağı) — aynı tablo DEĞİL.
  2. org_companies eski deleted_at timestamptz soft-delete kullanır; daha yeni kanonik entity'ler deleted boolean lifecycle — şema kasıtlı olarak burada tek-tip değil.
  3. service_id dört instance_* tablosunda uuid→text migrate edildi.
  4. Bazı org_users FK kolonları (department_id/profession_id/worker_level_id/working_schedule_id) FK-kısıtı olmayan stub'lardır (ileride wiring); cost_center_id + manager_user_id gerçek FK.
  5. Şema kaynağı: supabase/migrations/*.sql (50 dosya, kümülatif, 2026-08-24'e kadar — dizin-adı legacy; stack plain-PostgreSQL). apps/api/migrations/ bayat 10-dosyalık alt-küme.
  6. Bu şema migration-tanımlı (pilot-applied): pilot canlı-DB bu migration setinden bootstrap edildi + org-settings tabloları canlı-test edildi (create→gerçek Azure-PG persist). Birebir canlı-introspection istenirse ayrıca sağlanır.
