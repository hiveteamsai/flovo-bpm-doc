## 🆕 Eklenenler
- **Örnek süreç grubu `sampleProcess/expenseAndCreditCard/` (TASLAK) — 4 bağlantılı servis.** Kullanıcının eklediği 4 görselden
  süreç diyagramları (mermaid) + aksiyon/ServiceTrigger tabloları çıkarılıp **her servis için ayrı `.md`** oluşturuldu:
  - `expenseForm.md` (**Masraf Formu** — üst form; Form List + Yönetici/Muhasebe onayı; ServiceTrigger → Masraf) ·
    `expense.md` (**Masraf** — AI tarama + Parent Kontrol + Kullanıcı/ParentUser + 2 alt süreç; ServiceTrigger → Ekstre Satırı) ·
    `creditCardStatement.md` (**Ekstre** — Tutar alt süreci: kalan/kullanılan tutar) ·
    `creditCardStatementLine.md` (**Ekstre Satırı** — Masraf ilişkilendirme/kaldırma alt süreçleri; "Ekstre Tutar Alt süreç Başlat").
  - `index.md` (grup genel bakış + **servisler arası tetikleme zinciri** diyagramı: Masraf Formu → Masraf → Ekstre Satırı → Ekstre).
  - **Odak:** yeni **ServiceTrigger** + **triggerProcessStep** + **Üst Form Kullanıcı (ParentUser)** birlikte — v0.23 tasarımının uçtan uca örneği.
  - `sampleProcess/index.md`'ye grup satırı eklendi (çok-servisli, TASLAK).
  - **Açık (detaya):** başlangıç adı uyumlaması (Forma Ekle ↔ Masraf İlişkilendirme) · `targetPropertyId`/ilişki alanları ·
    Ekstre↔Ekstre Satırı tetikleme yönü · `parameters` (`expenseId`/`amount`) değer kaynağı.
- **Masraf Formu — önemli alanlar + iş kuralları eklendi** (`expenseForm.md`): `expenses` (**Form List** → Masraf; 3 başlangıç
  aksiyonu ile oluşturma **veya** taslak masrafları "var olandan ekle"; **ServiceTrigger'ın `targetPropertyId`'si**) ·
  `creditCardStatement` (**Form List** → Ekstre) · `creditCardStatementId` (**Textbox**). **İş kuralları:** **İK-1**
  `creditCardStatement` eklenince `enable=false` (`setViewForProperties`) → **max 1 ekstre**; **İK-2** ekstre eklenince ilk
  instance'ın `creditCardStatementId` değeri textbox'a yazılır (`assignValueToProperty`). ServiceTrigger tablosuna
  `targetPropertyId=expenses` sütunu işlendi. `creditCardStatement.md`'ye çapraz-referanslı `creditCardStatementId` alanı (kısmi) eklendi.
- **Ekstre servisi netleştirmeleri** (`creditCardStatement.md`): Başlangıç aksiyonu **ekstre oluştur** (`manual`) +
  **`actionDisplayType = invisible`** → ekstre **bağımsız oluşturulamaz**, yalnız Masraf Formu'ndaki ekstre Form List'i üzerinden.
  **ParentUser** (Üst Form Kullanıcı §3.22) ayarı: `parentServiceId`=**Masraf Formu**, `associatedPropertyId`=**ekstre Form List'i**
  → görüntüleme profili + aksiyon bekleyenler üst formdan devralınır. Ana + Tutar diyagramları da tırnaklı biçime çevrildi.
- **Ekstre — tam alan listesi + iş kuralları** (`creditCardStatement.md`): `creditCardStatementId` (**flowInfo→instanceId**;
  önceki "Textbox" düzeltildi) · `creditCardStatementLines` (**Form List** → Ekstre Satırı) · `totalAmount`/`remaningAmount`/
  `usedAmount` (**Numeric**). **İş kuralları (toplam):** `totalAmountAtama`/`remaningAmountAtama`/`usedAmountAtama` — satırların
  (`creditCardStatementLines[]`) ilgili alanını Σ toplayıp hedefe yazar (`assignValueToProperty`). **Açık:** `flowInfo` alan
  tipinin PropertyType karşılığı · iş kuralı ↔ Tutar alt süreci (kalan/kullanılan) örtüşmesi (kaynak hangisi?).
- **Ekstre Satırı — alanlar + iş kuralları** (`creditCardStatementLine.md`): `amount` (**tek enable**) · `remaningAmount` ·
  `usedAmount` (Numeric) · `used` (Checkbox) · `expenseIds` (**MultiselectCombobox → Masraf/`expense`**, `isAssociatedCombobox=false`,
  bilgi amaçlı) · `creditCardStatementId` (**parentProperty** → üst Ekstre'nin `creditCardStatementLines`'ından `creditCardStatementId`
  kopyalanır). **İş kuralları:** `remaningAmountAtama` (`amount-usedAmount`→remaningAmount) · `usedAtama` (`remaningAmount==0`→used) —
  `assignValueToProperty`/`fromCalculation`. **Döngü koruması tasarım-deseni netleşti:** `expenseIds` association kurmadığından
  (`isAssociated=false`) Masraf↔Ekstre Satırı **A→B→A döngüsü önlenir** → `service-trigger.md` + `todo.md` döngü-koruması maddesine
  bu örnek referans olarak eklendi. **Açık:** `parentProperty`/`flowInfo` alan tiplerinin PropertyType karşılığı.
  Başlangıç aksiyonu da düzeltildi: **satır oluştur** (`manual`) + **`actionDisplayType=invisible`** → satır bağımsız oluşturulamaz,
  yalnız Ekstre'nin `creditCardStatementLines` Form List'i üzerinden (Ana diyagram tırnaklı biçime çevrildi).
- **Masraf — alanlar + iş kuralı** (`expense.md`): `amount` (Numeric) · `expenseId` (**flowInfo→instanceId**) ·
  `creditCardStatementId` (**parentProperty** → Masraf Formu.`expenses`'ten kopyalanır) · `creditCardStateLine` (**Combobox**,
  **`isAssociatedCombobox=true`**, `associatedServiceId=creditCardStatementLine`). **İş kuralı** `crediCardStatementLineDoldurma`
  (**`fillDataSource`**): `creditCardStatementId` eşit **ve** `used==false` olan Ekstre Satırı instance'larını combobox veri
  kaynağına doldurur (aynı ekstre + kullanılmamış). **Zincir kapandı:** `creditCardStateLine` = Masraf ServiceTrigger'ının
  `targetPropertyId`'si (isAssociated=true → tetikler); Ekstre Satırı.`expenseIds` isAssociated=false → geri-tetiklemez (döngü yok).
  ServiceTrigger tablosuna `targetPropertyId=creditCardStateLine` işlendi.
- **Senaryo dosyası** (`scenarios.md`): süreç örneği uçtan uca senaryolarla detaylandırıldı. **5 senaryo yazıldı:**
  **(1)** bağımsız masraf oluşturma (Parent Kontrol false → Kullanıcı/Taslak) · **(2)** Form List üzerinden oluşturma
  (AssociatedInstance → whenAddedAssociate → Forma Ekle alt süreç [Status false, no-op] · ana akış AI→Bildirim→Parent Kontrol
  [expenseFormId dolu → true] → ParentUser) · **(3)** var olan Taslak masrafı sonradan ekleme (Status Taslak → true →
  triggerProcessStep → Forma Ekle webhook → Kullanıcı→ParentUser) · **(4)** **ekstre kurulumu + Masraf↔Ekstre Satırı eşleştirme**
  kaskadı (Aşama A: İK-2 → parentProperty → `fillDataSource` [creditCardStatementId eşit + used==false]; Aşama B: satır seçimi →
  AssociatedInstance → whenAddedAssociate → Ekstre Satırı Forma Ekle → Ekstre Tutar Başlangıcı → satır güncellenir) · **(5)**
  formdan çıkarma **kaskadı** (whenRemoveAssociate → Formdan Çıkart → değerAtama `creditCardStateLine` temizler → expense↔satır
  association kalkar → Ekstre Satırı Formdan Kaldırma → Ekstre Tutar Başlangıcı [expense parametreleriyle] → satır güncellenir).
  Senaryo 4 (ekleme) ↔ Senaryo 5 (kaldırma) simetrik. **Netleşen davranışlar** `expense.md`'ye işlendi:
  **Parent Kontrol = `expenseFormId` dolu mu**; **Kullanıcı** = ilişkilendirilmemiş bekleme, **ParentUser** = ilişkilendirilince
  üst formun adımına göre davranış. `index.md`'ye "Senaryolar" bölümü + link eklendi.
- **Eksik alan tamamlandı — `expenseFormId`:** `expenseForm.md`'ye `expenseFormId` (**flowInfo→instanceId**); `expense.md`'ye
  `expenseFormId` (**parentProperty** → Masraf Formu.`expenses`'ten kopyalanır) → masrafın hangi masraf formuna ait olduğu.
  (creditCardStatementId ile aynı parentProperty deseni.)

## 🔧 Değişenler / kararlar
- **ServiceTrigger — örnekle netleştirildi (kaynak ↔ hedef instance ayrımı).** expenseAndCreditCard örneği, modelin **`instanceId`
  (yürütme hedefi)** tarafını hiç anmadığını ortaya çıkardı. Düzeltildi (`models/service-settings/service-trigger.md`):
  - **`parameters` kaynağı = `associatedInstanceId`** (üst form) · **yürütme hedefi = `instanceId`** (targetService'teki **mevcut**
    instance; değişmez `Instance(instanceId).serviceId == targetServiceId`). Associate alt süreci **yeni instance/süreç oluşturmaz**;
    hedef instance üzerinde **yardımcı dal** olarak koşar — statüsünü okur ve içindeki `triggerProcessStep` ile **o instance'ın ana
    akışındaki** aksiyonu (Forma Ekle/Formdan Çıkart) tetikler. Önceki **yanlış** "yeni alt ProcessInstance / `parentProcessInstanceId`
    = `associatedInstanceId`'nin süreci" ifadesi düzeltildi ("yeni ana ProcessInstance" **yalnız timer** için).
  - **`whenRemoveAssociate` parametre zamanlaması:** hedef instance + `parameters`, ilişki satırı **silinmeden önce/anında** çözülür.
  - **Yeni açık noktalar:** `async` **kaskad kompozisyonu** (üst üste `async=false` → senkron derinlik; Senaryo 5) · alt sürecin mevcut
    instance üzerinde **çalışma mekaniği** (yardımcı ProcessInstance ↔ mevcut sürecin dalı). → `todo.md` + service-trigger.md "Açık noktalar".
  - Ayrıca `models/processInstances/associated-instance.md` tüketici notu (hedef=`instanceId`) güncellendi.
